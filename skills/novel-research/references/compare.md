# 跨书专题

## 入口与工作区

用户可直接提出跨书问题，或使用可选动作 `compare <专题目录> <书籍目录1> <书籍目录2> […] [问题]`。已有专题可用 `compare <专题目录> [问题]`，也可自然语言继续讨论。动作由宿主 Agent 解释，不能直接传给 Python CLI。

每本书保持独立工作区；专题登记至少两本书的位置，保存比较报告与专题讨论，不复制正文或重新运行全部分析。不要求用户手写配置。版本、改编、增补篇和外传可以作为独立书籍登记；作品关系由证据与用户提供的背景确定，不能仅凭同名人物自动合并设定或时间线。

先找到参与书籍的真实路径，将相对路径按用户当前项目解析为绝对路径。专题应位于各书工作区之外，例如同一项目下的两个书籍目录和一个专题目录。用户未指定专题路径时，复用当前项目中参与书籍匹配的已有专题；没有则建立名称明确的独立子目录并告知路径。多份候选存在实质歧义时才询问。

开始、恢复或继续跨书研究时，**先识别 `topic.json`，再执行分书接入**：

1. 已有专题先读取 `topic.json` 的书籍登记；首次专题使用用户提供的书籍目录。
2. 对每本书分别按 [资料接收](intake.md) 扫描新增文件、处理 EPUB、登记并准备发生变化的来源。已准备且未改变的来源直接复用。不要在专题根目录执行 `sources scan`、`prepare`、`task next` 或 EPUB 转换。
3. 依次读取各书的 `status`、相关 `notes recall`，以及专题自己的 `status`、`notes recall`。专题 `status.cases` 给出各调查的 `stale` 和 `needs_review`；读取相关报告与阶段记录，处理复核提示，`check --rebuild` 可更新入口。参与书籍不必先完成全书粗读或精读；需要时按当前问题检索原文。
4. 首次登记或追加书籍时运行下方 `topic init`；已有专题日常查询无需重新初始化。用户只有建立专题的要求、没有具体问题时，展示参与书籍、可用资料与入口，等待其研究问题，不自行开展无边界的全面比较。

脚本统一前缀：

```text
<Python解释器> "<skill目录>/scripts/novel.py" --workspace "<专题目录>"
```

```text
topic init "<书籍1绝对路径>" "<书籍2绝对路径>" --title "人物认知对照"
status
```

专题目录可由工具创建。`topic init` 幂等，后续可追加书籍；相对书籍路径按专题目录解析，所以 Agent 统一传绝对路径。登记保存在 `topic.json`，旧配置保留历史。复制同一书籍工作区不会成为另一部独立作品；若路径中仍是同一书籍身份的副本，须核对原工作区，不能修改身份来跳过检查。

## 查询与原文核对

```text
search "身份" --in analysis --limit 20
search "怀疑" "确认" --in text --limit 20
search "身份" --in text --book "<书籍ID>" --chapter-from 1 --chapter-to 5
read --book "<命中返回的book_id>" --span "<span_id>" --limit 3000
search "身份" --in supplements --kind commentary
notes recall --query "身份"
```

专题检索正文、补充资料和各书当前的粗读/精读分析。省略 `--book` 时搜索所有参与书籍；可重复指定以选择多本书。按返回的 `next_offset` 翻页。每条命中带 `book_id`、`book_title`、`book_workspace_id`；原文还带来源版本、章节和片段位置。读取原文必须同时传 `--book`，相同的 `span_id` 在不同书中可能重复。

`--revision` 指定工具返回的 `topic_rev_…`，工具据此读取各书当时的来源快照。分析检索仅查询各书当前有效分析，不接受历史版本或章节过滤；命中仍是导航，须回查原文。专题 `notes recall` / `search --in notes` 仅查询专题讨论；各书的讨论和纠错在其各自工作区查询，不能因为专题笔记未命中就断言原书没有纠错。

同一组章节参数会分别约束选中书籍的正文章序号，**章号相同不证明事件相同**。需要不同章节范围时分别查询。保持各书叙述、角色认知和版本各自独立，比较先后关系、补写、改写或矛盾时给出两侧原句和上下文。分歧尚不能确定时，保留多个解释及未决项，不强行归并为统一事实。

## 保存比较结论与讨论

复用 [研究与讨论记录](research.md) 的字段、分类和保存流程。跨书证据必须包含 `book_id`；所有 ID、版本和引文取自真实工具结果。宿主写入专题 `.novel/inbox/compare.json`，例如：

```json
{
  "case_id": "identity-comparison",
  "question": "两部作品对同一人物认知的描写有何联系与差异？",
  "scope": {
    "books": {
      "替换为书籍1的book_id": {"chapter_from": 1, "chapter_to": 5},
      "替换为书籍2的book_id": {"chapter_from": 1, "chapter_to": 3}
    }
  },
  "findings": [
    {
      "kind": "inference",
      "text": "根据两侧实际引文填写比较判断，并区分已证实内容和解释。",
      "evidence": [
        {"book_id": "替换为书籍1的book_id", "span_id": "从工具返回值复制", "quote": "第一本书的准确连续原句"},
        {"book_id": "替换为书籍2的book_id", "span_id": "从工具返回值复制", "quote": "第二本书的准确连续原句"}
      ],
      "counter_evidence": []
    }
  ],
  "queries": ["分别记录各书实际检索的表达、章节和材料范围"],
  "hypotheses": [],
  "unresolved": []
}
```

`scope.books` 可省略，默认所有参与书籍的正文；提供时仅允许所列书籍，各书可有独立章节与 `source_kinds`。全局 `chapter_from` / `chapter_to` / `source_kinds` 作为默认值，各书可覆盖；补充资料仍须显式纳入对应来源类型，且不按正文章号过滤。输入 `source_revision` 时使用本次查询返回的专题版本，不把某一本书的 `rev_…` 填在这里。

```text
research save ".novel/inbox/compare.json"
research render identity-comparison
check --rebuild
```

报告保存在 `research/<case_id>/report.md`，每条引文带所属书籍、来源版本与位置。`library.md` 是专题入口，列出参与书籍、报告和复核状态；专题讨论、研究假设、纠错与阶段进度保存在 `notes/`。有价值的比较结果应保存为研究记录；阶段结束时用 `checkpoint` 笔记保留各书已查范围、未决项和下一步。

专题中的 `notes save` 也使用带 `book_id` 的证据，支持 `pending` / `applied` 更正及撤回。`target_id` 仅能关联专题中已保存的记录；纠正某一本书自身的分析时，在该书工作区另存更正，再重新检查专题。来源与人物关系的语义判断仍由 Agent 核实，程序只校验引用与范围。

## 变化、恢复与备份

参与书籍准备了新版本，或出现新增纠错/撤回时，专题旧报告标记需要复核；尚未准备的已登记来源变动也会提示。普通偏好和阅读进度不会使比较结果过期。当前按参与书籍提示复核，可能包含与本问题无关的变化；不会自动改写报告结论。

复核时读取旧报告和有效纠错，再分别查询当前原文，保存同一 `case_id` 的新研究记录并重新生成报告。每条研究记录固定当时的专题来源版本，旧 JSON 及原引文保留；显式重试同一 `id` 时仍绑定其原版本。增加参与书籍也会提示旧报告复核。不要改旧记录中的版本号或让工具把历史证据静默替换成新原文。

`resume <专题目录>` 恢复专题讨论与阶段笔记，先处理复核标记，不自动启动各书全书分析。专题没有独立的逐章任务或合并阅读进度。

备份、迁移时保留专题目录及所有参与书籍的完整工作区，包括隐藏 `.novel/`。专题只保存书籍位置、来源版本元数据和引用记录，没有独立保存整本原文。保持相对目录关系即可整体迁移；跨 Windows 磁盘的路径可能为绝对路径，迁移后需由 Agent 重新登记失效路径。找不到书籍或身份不一致时先定位原工作区，不能把同名目录当作原书继续写入。
