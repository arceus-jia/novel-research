# 分批粗读与概览建库

用户使用 `skim [小说目录] [章节范围]` 或明确要求粗读、快速通读时使用。目录明确后直接执行；未限定章节时读取全书正文，不再询问要分析具体剧情还是全文。粗读逐批阅读目标范围，保留简短梗概、主要人物、关键事件和待查线索；不自动开展精读或跨章专题调查。输入仍使用当前宿主模型的用量，粗读主要减少细节抽取与输出。

## 准备与领取任务

先按 [intake.md](intake.md) 接入资料、转换 EPUB、确认章节和准备快照。所有命令使用已确认的解释器、脚本绝对路径及 `--workspace "<小说目录>"`。默认全书时执行：

```text
status --mode skim
notes recall --limit 20
task next --mode skim
task submit "<小说目录>/.novel/inbox/skim.json"
```

用户指定章节时在 `task next --mode skim` 后加对应的 `--chapter-from` / `--chapter-to`，保持本次范围。每次只读返回的任务片段，长章可能分为多个任务；实际读完本任务再生成记录，不抽样冒充通读。理解关联内容时可检索已有分析和必要原文，不一次加载全书或所有历史梗概。

## 简洁但可回查的记录

与精读使用相同条目结构，`mode` 可省略；任务 ID 已绑定阅读模式，不能把精读 ID 改标为粗读，或将粗读结果计为精读完成。

```json
{
  "task_id": "从粗读任务包复制",
  "input_fingerprint": "从粗读任务包复制",
  "mode": "skim",
  "overview": "本任务范围内的简短情节梗概，保留事件顺序与重要转折。",
  "mentions": [],
  "claims": [],
  "open_questions": []
}
```

梗概必须非空，只作导航。根据实际内容，少量补充下列条目，无须穷举人物、所有对话与心理变化：

- `mentions`：本批主要人物的原文称谓与证据，不据称谓猜定身份。
- `claims`：后续定位值得保留的关键事件或转折；区分叙述、人物说法、认知和推断，附准确原句。结构与类型见 [analyze.md](analyze.md)。
- `open_questions`：值得后续精读的疑问或线索；可以附触发问题的原句，不能把猜想写成事实。

没有适用条目时保留空数组。粗读沿用精读的引用校验，不能因追求速度编造原句、章节或判断。一般格式问题最多修复两次；继续失败时保留草稿和诊断，不计完成。

## 连续执行与完成

提交成功后继续领取同模式、同范围的任务，直到目标范围完成、用户要求停止或宿主资源限制需要暂停。粗读和精读各自保存正式记录，`status --mode skim` 与 `status --mode analyze` 分别查看完成度。范围内 `task next` 返回 `complete` 不等于全书完成；全书粗读完成还须核对 `status --mode skim` 的 `coverage_complete`、目录和转换提示。

四个 `analysis/views/` 文档汇总两种模式并标注进度，详细记录在 `analysis/records/`。粗读结果可用于定位，但研究关键判断仍回查原文；之后执行 `analyze` 会领取独立的精读任务，可借助粗读导航，不能直接跳过精读。

模式与章节范围由工具保存。新会话使用 `resume` 时先查看 `status` 的 `reading_session`、读取有效笔记，再无参数 `task next` 恢复原模式与范围；显式 `skim` / `analyze` 则分别传 `--mode skim` / `--mode analyze`，未指定章节时回到全书。旧工作区无阅读断点时默认按精读全书恢复。

阶段结束用 `notes save` 保存 `checkpoint`，写明模式、范围、已处理内容、未决问题及下一步。保存成功后才报告进度已持久化；宿主结束后没有后台模型继续阅读。
