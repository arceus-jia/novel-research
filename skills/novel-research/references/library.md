# 首次全书精读与资料库

用户要求“通读一遍”“详细建库”“先把这本书吃透”或继续这类工作时使用。解释这是宿主逐批读原文、保存结果并跨章复核，会消耗当前模型的用量；脚本不在后台调用另一个模型。具体问题仍可直接研究，不必等待建库完成。

## 新书引导

首次接入且用户尚未提出具体问题时，简短说明两种用法：先全书精读建资料库，或直接提问、按需查证。只需确认影响工作量的选择；用户已经要求精读时直接开始。先完成接收资料、目录核对和一个可读片段的检查，再报告预计阅读范围，不把导入或转换说成已经读完。

所有命令都加已确认的解释器、脚本绝对路径及 `--workspace "<小说目录>"`。首次资料接收先读 [intake.md](intake.md)；EPUB 先转换，保留并检查转换提示。正文、前言、番外、脚注和评论的范围要明确；不能把未提取的图片当作读过。核对 `status --chapters` 的全部分页及 `needs_review`，目录有歧义时按 [setup.md](setup.md) 计算分章范围，不改用户原文。

## 第一遍：逐批阅读并保存

读取 [analyze.md](analyze.md)，用已有任务格式完成下面的循环：

```text
status
notes recall --limit 20
task next
task submit "<小说目录>/.novel/inbox/analysis.json"
```

每项任务实际阅读 `result.task.spans`；长章可能包含多个任务。每次提交成功再领取下一项，直到全书当前任务处理完、用户要求停止或宿主资源限制需要暂停。不要把全书原文、所有章卡或旧聊天一次性加载；为理解本批内容，按人物称谓、事件、物件或意象查询相关的已有分析，再回查必要原文。

“详尽”体现在保留后续研究所需的具体证据和变化，而非把每批压成一句情节梗概。按实际内容填写，空缺可以保留，不为凑栏目制造结论：

| 材料 | 保存方式 |
| --- | --- |
| 人物称谓、初次出现、身份歧义 | `mentions` 保留原文称谓与引文；身份猜测另列问题 |
| 事件、地点、相对时间、明确的因果或状态变化 | `claims` 的 `narration`；区分叙述顺序与实际发生顺序 |
| 对话中的承诺、隐瞒、相互矛盾说法 | `speech`；说法是否真实另作核查 |
| 谁看见、听说、怀疑、误以为、确认了什么 | `belief`；保留认知主体、证据来源和原文强度 |
| 动机、关系变化、潜在伏笔、意象与写法 | 有依据的 `inference` 或 `interpretation`，不晋升为叙述事实 |
| 未解身份、时间矛盾、可能回收的线索与反例 | `open_questions`；尽量保留触发问题的原句 |

每条主张只表达可核查的一个要点，带有足够上下文的连续原句。只凭当前任务不能确认的后文回收先列为问题；第二遍再调查。目录/转换提示不能靠猜测消除，保存尚未覆盖的部分。

章卡已存在时先评估能否满足本次详尽程度。兼容任务会跳过已接收内容；计数完成不代表资料足够细。补漏时重新查相关原文，把新增发现保存为研究或讨论记录；用关联纠错修正旧结论，不覆盖不可变章卡，也不为重新阅读而删除记录。

## 第二遍：围绕问题跨章复核

第一遍后运行 `check --rebuild`，查看 `analysis/views/library.md`、`chapters.md`、`characters.md`、`questions.md`。这些视图可以重建，正式分析记录和原文快照是依据。`questions.md` 收集阅读时的问题，可能已在后续解决；它不是自动更新的“全部未解谜题”。

结合用户兴趣与第一遍的问题，选择实际值得整理的专题；无需为每本书机械生成全部报告。常见专题是人物动机与关系、认知变化、事件时间线、伏笔候选及回收、叙述方式。按 [research.md](research.md) 保存有支持证据、反证、替代解释和未决项的报告。

可先用 `search "<称谓或线索>" --in analysis` 找章卡与问题，再组合原文查询、读上下文。全书已读过也不能仅从摘要推导“首次”“从未”“所有”；主动检查别称、相关说法、早期误导和反面证据。伏笔需区分“早期出现”“后文呼应”“解释为预先设计”，作者意图没有资料时保持解释性质。

报告放 `research/<主题>/report.md`，有效纠错和讨论进度通过 `notes recall` 读取。用户需要总览时，在阶段检查点中列出已生成的专题与文件位置、主要争议及下一步；不把 Agent 之间或 Agent 自己的推断写成用户共识。

## 完成、暂停与恢复

只有全书范围的 `status.coverage_complete` 为真，且已说明转换提示与实际覆盖范围，才报告第一遍阅读任务完成。它不证明已抽取全部事实，更不代表第二遍专题研究已全部完成。分别说明：正文范围、已接收/待处理任务、目录和转换缺口、已有报告、未决问题。

每个有实质进展的阶段用 `notes save` 保存 `checkpoint`，内容包含工作阶段、来源版本、已查范围、重要问题、报告位置和下一步。中断前说明剩余工作；保存成功后才说断点已记录。

新会话继续同一个工作区：先扫描新增资料，检查来源变化，再 `status`、`notes recall`、`task next`；已经接收的兼容任务可复用。EPUB 改版先重新转换再 `prepare`。不依赖模型缓存，也不承诺宿主结束后仍无人值守读完。
